# بوابة بشراكم — تجربة HTML مع رفع إلى السيرفر

## تحديث رابط الرفع — ٢٢ سبتمبر ٢٠٢٦

- فك ضغط حزمة التحديث الجديدة واستبدل أربعة ملفات فقط في المستوى الرئيسي لمستودع bshrakm: index.html وapp.js وdemo-store.js وREADME.md. ملفات التنسيق والصورة لا تتغير في هذا التحديث.
- رابط الرفع: `http://192.168.91.133:3000/upload`، ومكان تغييره هو ثابت `UPLOAD_URL` أعلى demo-store.js.
- يرسل الزر طلب POST من نوع FormData بحقل واحد اسمه `file`، مطابقًا للكود المرسل. لا يُضبط Content-Type يدويًا؛ المتصفح يضيف حد multipart الصحيح.
- تُفحص الجلسة وصلاحية الرفع والمجلد والحجم والامتداد والحصة المحلية قبل الاتصال بالسيرفر. تظل هذه الفحوص تجريبية في المتصفح، ويجب أن يطبق السيرفر صلاحياته وحدوده بنفسه.
- لا تسجل البوابة الملف على أنه مرفوع إلا بعد استجابة HTTP ناجحة ورد JSON يؤكد النجاح. جُرّب السيرفر بملف نصي صغير مولّد للاختبار ونجح برد HTTP 200، واحتوى رده على message وfileName وpath. حقل path مسار تخزين داخل السيرفر، وليس رابط تنزيل.
- الملف التجريبي المرسل اسمه bushrakom-connection-test-20260922.txt، وأعاد السيرفر الاسم 1790026572706-bushrakom-connection-test-20260922.txt.
- بعد نجاح الإرسال تُحفظ نسخة محلية ومعلومات الملف، لتستمر قائمة الملفات والتنزيل والمشاركة التجريبية. عند فشل حفظ النسخة المحلية تظهر رسالة توضح أن الرفع إلى السيرفر نجح؛ لا تكرر الإرسال لنفس الملف.
- لا يوجد إعادة إرسال تلقائية. عند انقطاع الشبكة أو إلغاء الطلب بعد بدء الإرسال قد يكون السيرفر استلم الملف؛ تحقق منه قبل إعادة المحاولة.

### ما يرتبط بالسيرفر الآن

الرفع فقط. تنظيم المجلدات والأسماء والمشاركة والحذف والسلة والنسخ الاحتياطي ما زال محليًا في المتصفح. اختيار المجلد لا ينشئ مجلدًا على السيرفر، لأن عقد الرفع المقدم يستقبل حقل file فقط. إعادة تسمية الملف أو حذفه محليًا لا تغير نسخة السيرفر. الملفات القديمة لا تُرفع تلقائيًا، واستعادة نسخة احتياطية لا ترفع الملفات إلى السيرفر.

ربط قائمة الملفات والتنزيل والحذف والمجلدات والحسابات مركزيًا يحتاج روابط API الخاصة بهذه العمليات. هذا التحديث لا يحوّل الحسابات المحلية إلى حسابات خادم.

### الاتصال من GitHub Pages

يجب أن يكون جهاز المستخدم قادرًا على الوصول إلى شبكة 192.168.91.133، وأن يكون السيرفر يعمل على المنفذ 3000. نجح فحص OPTIONS، وأعاد السيرفر Access-Control-Allow-Origin: *؛ يجب أن تستمر ترويسات CORS بالظهور في ردود الرفع والأخطاء. أصل الموقع هو https://swwa71.github.io دون مسار /bshrakm/.

قد يطلب Chrome إذن الوصول إلى الشبكة المحلية عند الرفع من صفحة HTTPS. المتصفحات التي لا تدعم استثناء الشبكة المحلية قد تمنع الاتصال بعنوان HTTP من GitHub Pages؛ عندها يلزم عنوان HTTPS صالح للسيرفر أو نشر الواجهة والسيرفر من أصل مناسب. لا يحتاج التحديث إلى تعطيل حماية المتصفح.

راجع [إرشادات Chrome للشبكة المحلية](https://developer.chrome.com/blog/local-network-access) و[شرح CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS).


واجهة عربية بخط تجوّل (Tajawal)، تستخدم خلفية الجهة وشعارها. تعمل بملفات ثابتة دون تثبيت حزم أو خطوة بناء.

لمشاهدة مقدمة الدخول، سجّل الخروج ثم حدّث الصفحة: يظهر الشعار في المنتصف، يتوقف قليلًا، ثم يرتفع ويصغر، وتظهر خانات الدخول بعده. تستغرق المقدمة نحو ٣٫٣ ثوانٍ. يحترم الموقع إعداد تقليل الحركة في الجهاز.

## مسؤول النظام

- إنشاء حسابات وتعديل الأسماء وكلمات المرور والأدوار، ومنح دور المسؤول؛ لا يوجد حذف للحسابات.
- تفعيل الحساب أو إيقافه، وإنهاء جلساته، وفك القفل المؤقت. لا يمكن إيقاف آخر مسؤول مفعّل أو سحب دوره.
- تحديد مجلدات كل مستخدم، أو السماح بجميع المجلدات الحالية والمستقبلية.
- تحديد صلاحيات الرفع والتنزيل وإعادة التسمية والنقل والحذف والمشاركة لكل مستخدم عادي.
- إنشاء المجلدات وتعديل أسمائها، وإدارة ملفات النظام ونقلها وحذفها إلى السلة واستعادتها.
- التحكم بالمشاركة العامة، وحد حجم الملف والامتدادات المسموحة، والمساحة المخصصة لكل مستخدم.
- مشاهدة عدد المستخدمين والملفات والمساحة، وسجل العمليات الذي يوضح المستخدم والعملية والعنصر والوقت.
- تنزيل نسخة احتياطية وفحصها واستعادتها، بما يشمل الحسابات والصلاحيات ومحتوى الملفات والسلة والسجل.

## المستخدم العادي

- تسجيل الدخول وتغيير كلمة المرور، ومشاهدة ملفاته والمجلدات المسموحة له.
- اختيار مجلد قبل الرفع، والبحث باسم الملف أو المالك أو المجلد، وعرض حجم الملف وتاريخ رفعه.
- تنزيل الملفات، وتعديل ملفاته أو نقلها أو حذفها، وفق الصلاحيات التي منحها المسؤول.
- مشاركة ملف محدد أو جميع ملفاته مع مستخدم آخر، وإلغاء المشاركة. المستلم يحصل على الاطلاع والتنزيل فقط، ضمن مجلداته المسموحة وصلاحية التنزيل لديه.
- مشاهدة المساحة المستخدمة والمتبقية وتسجيل الخروج. تنتهي الجلسة بعد ١٥ دقيقة من عدم النشاط.

## قواعد التجربة

- اسم المستخدم يقبل الحروف أو الأرقام أو مزيجًا منهما دون مسافات. كلمة المرور من ٤ إلى ٢٠ خانة دون اشتراط نوع معين.
- يُقفل الحساب لمدة ١٥ دقيقة بعد خمس محاولات دخول فاشلة متتالية. يستطيع المسؤول فك القفل أو إعادة تعيين كلمة المرور.
- إيقاف الحساب وتغيير صلاحياته أو بيانات دخوله ينهي جلساته. تفحص الواجهة الجلسة كل خمس ثوانٍ أثناء فتحها، وكذلك عند العودة إليها وتنفيذ العمليات.
- الحد الأعلى للملف في الواجهة ١ جيجابايت (١٬٠٧٣٬٧٤١٬٨٢٤ بايت)، ويمكن للمسؤول تقليله. الامتدادات الفارغة تعني السماح بجميع الأنواع؛ تتطبق الحدود على الرفع الجديد وإعادة التسمية.
- المساحة الافتراضية لكل حساب ٢ جيجابايت ويمكن تعديلها، مع بقاء حد الملف الواحد ١ جيجابايت. خفض المساحة لا يحذف الملفات الحالية. حصة المتصفح الفعلية قد تكون أقل.
- الملفات في السلة تحتسب ضمن مساحة مالكها. الاستعادة تعيد الملف إلى مجلده الأصلي. أذونات مشاركة الملف المحدد تُزال عند حذفه؛ أذونات مشاركة جميع ملفات المالك تنطبق عليه مجددًا عند استعادته.
- المجلدات المسموحة شرط مستقل عن المشاركة. مشاركة ملف لا تمنح تلقائيًا صلاحية مجلده.
- سجل العمليات يبدأ من التحديث؛ لا يمكن إنشاء سجل لعمليات قديمة لم تكن مسجلة سابقًا.

## النسخ الاحتياطي

من «إدارة النظام» اختر «تنزيل نسخة احتياطية». تنتج التجربة ملفًا بامتداد `.bshbak` يشمل البيانات ومحتوى الملفات. احتفظ به في مكان خاص؛ النسخة غير مشفرة.

للاستعادة، اختر الملف ثم «فحص النسخة». ستظهر أعداد المستخدمين والملفات والمساحة قبل التأكيد. الاستعادة تستبدل بيانات التجربة الحالية بالكامل وتُنهي الجلسات؛ سجّل الدخول بعدها بحساب من النسخة المستعادة. نزّل نسخة من البيانات الحالية أولًا إذا أردت الاحتفاظ بها. إذا تعذّر الحفظ بسبب مساحة المتصفح، لا تعتمد المعاملة تغييرات جزئية.

## حدود نسخة HTML

هذه نسخة للعرض والتجربة، وليست بوابة مركزية لحفظ بيانات الموظفين الفعلية. الحسابات والأذونات والملفات محفوظة داخل المتصفح باستخدام IndexedDB؛ يمكن لصاحب الجهاز تعديلها. ترسل الملفات الجديدة إلى سيرفر الرفع المحدد أعلاه، وتبقى البيانات الإدارية والنسخ المحلية في المتصفح. لا ترسل الملفات إلى GitHub.

المشاركة وإنهاء الجلسات هنا محاكاة بين حسابات النسخة في المتصفح نفسه وعلى عنوان الموقع نفسه. لا تنتقل البيانات أو الصلاحيات تلقائيًا بين أجهزة الموظفين. النشر على GitHub Pages لا يغيّر ذلك؛ التشغيل المركزي الفعلي يحتاج خدمة خلفية وتخزينًا مشتركًا.

حذف بيانات الموقع أو التصفح الخاص قد يفقد البيانات. استخدم ملفات تجريبية واحتفظ بنسخ احتياطية. تتطلب عمليات الرفع الجديدة اتصالًا بالسيرفر؛ الخط مضمّن في التنسيق، وترخيصه محفوظ فيه. الصورة والشعار للجهة صاحبة الهوية.
