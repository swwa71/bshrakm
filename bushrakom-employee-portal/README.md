# بشراكم — بوابة الموظفين

بوابة عربية لإدارة حسابات الموظفين والملفات والمجلدات وأذونات الاطلاع. تستخدم صورة جمعية بشراكم المرفقة خلفيةً لصفحة الدخول، وتعيد عرض الشعار في صفحة الدخول ورأس البوابة دون تعديل الصورة الأصلية.

## التشغيل لأول مرة

المتطلب الوحيد: [Node.js](https://nodejs.org/en/download) الإصدار **24.14 أو أحدث**. لا توجد حزم خارجية ولا تحتاج إلى `npm install`.

1. فك ضغط المشروع وافتح الطرفية داخل مجلد `employee-portal`.
2. انسخ ملف الإعدادات. على Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   على Linux أو macOS:

   ```sh
   cp .env.example .env
   ```

3. أنشئ مسؤول النظام الأول:

   ```sh
   npm run setup
   ```

   أدخل الاسم الظاهر، ثم اسم المستخدم، ثم كلمة المرور مرتين. كلمة المرور مخفية أثناء الكتابة. لا توجد بيانات دخول افتراضية. يعمل الإعداد الأولي مرة واحدة؛ إنشاء بقية الحسابات وتعديلها يكون من البوابة.

4. شغّل البوابة:

   ```sh
   npm start
   ```

5. افتح **http://localhost:3000** وسجّل الدخول بالحساب الذي أنشأته. استخدم الرابط نفسه كما هو؛ التحقق من مصدر الطلب مرتبط بـ `APP_ORIGIN`.

يمكن تشغيل الأوامر مباشرةً إذا لم يتوفر npm:

```sh
node --env-file-if-exists=.env server.mjs setup
node --env-file-if-exists=.env server.mjs
```

## استخدام البوابة

### مسؤول النظام

- إنشاء المستخدمين بأسماء مستخدمين تحتوي حروفًا فقط أو أرقامًا فقط أو مزيجًا. تدعم الأسماء العربية، ولا يسمح بالمسافات أو محارف التحكم؛ الحد الأقصى 64 خانة. لا تختلف أسماء المستخدمين بتغيير حالة الحروف الإنجليزية.
- تعديل الاسم واسم المستخدم وكلمة المرور والصلاحية. ترك كلمة المرور فارغة في التعديل يحافظ على السابقة.
- منح مستخدم آخر صلاحية مسؤول النظام أو إعادته إلى مستخدم عادي. لا يمكن إزالة صلاحية آخر مسؤول نظام.
- لا توجد عملية لحذف حسابات المستخدمين، في الواجهة أو واجهة الخادم.
- إنشاء المجلدات وتغيير أسمائها. يبدأ النظام بثلاثة مجلدات قابلة لإعادة التسمية: المستندات العامة، التقارير، النماذج.
- فتح المشاركة بين المستخدمين أو إغلاقها في أي وقت. عند الإغلاق تتوقف إمكانية الاطلاع على ملفات الآخرين، وتُحفظ الأذونات لتعود عند الفتح. يستطيع صاحب الملفات إلغاء إذن محفوظ حتى أثناء الإغلاق.
- صلاحية إدارة الحسابات لا تعطي وصولًا تلقائيًا إلى ملفات الآخرين؛ يحتاج المسؤول إلى إذن صاحبها مثل بقية المستخدمين.

### جميع المستخدمين

- رفع الملفات بعد اختيار مجلد؛ يرفض الخادم الرفع دون مجلد صحيح، حتى عند تجاوز الواجهة.
- الحد الأقصى للملف **1 GiB = 1,073,741,824 بايت**. يقبَل النظام جميع أنواع الملفات، ويحفظها على القرص بالتدفق دون تحميل الملف كاملًا في الذاكرة.
- عرض الملفات الخاصة وتنزيلها، وتغيير اسم الملف أو نقله إلى مجلد آخر، وحذف الملف بعد التأكيد.
- منح مستخدم آخر إذن الاطلاع والتنزيل لجميع الملفات الحالية والمستقبلية، أو إلغاء الإذن. الإذن لا يشمل التعديل أو الحذف.
- عرض الملفات المشتركة من قسم «ملفات مشتركة معي». لا توجد روابط عامة للملفات.

### كلمات المرور والجلسات

- كلمة المرور من **4 إلى 20 خانة**، دون اشتراط نوع محدد: أرقام، حروف، رموز أو مزيج منها. لا تُحذف المسافات من كلمة المرور.
- تُخزن كلمات المرور باستخدام `scrypt` مع قيمة عشوائية لكل كلمة مرور؛ لا تُخزن كنص صريح.
- تنتهي الجلسة على الخادم بعد **15 دقيقة من عدم النشاط**. يُقفل العرض ويُطلب تسجيل الدخول عند العودة. القراءة الآلية وتحديث البيانات لا يمددان الجلسة، والتفاعل الفعلي في الصفحة يرسل تأكيد نشاط قصيرًا للخادم.
- بدء التنزيل لا يمدد الجلسة تلقائيًا. الرفع الذي يستمر أكثر من مدة الجلسة دون أي تفاعل يُرفض عند انتهائه، وتُنظّف بياناته المؤقتة.
- تغيير اسم الدخول أو كلمة المرور أو الصلاحية يلغي جلسات المستخدم الحالية، ويطلب منه إعادة تسجيل الدخول.
- تحديد محاولات الدخول: 10 محاولات خاطئة خلال 15 دقيقة للحساب أو عنوان الاتصال. كلمات المرور القصيرة مسموحة وفق المتطلبات.

## ملفات المشروع

```text
employee-portal/
├── public/
│   ├── index.html       # صفحات الدخول والبوابة والنوافذ
│   ├── styles.css       # تصميم عربي متجاوب
│   ├── app.js           # تفاعلات الواجهة والجلسة والرفع
│   ├── background.png   # الصورة الأصلية المقدمة من صاحب المشروع
│   └── favicon.svg      # أيقونة البوابة
├── test/
│   └── portal.test.mjs  # اختبارات الصلاحيات والتخزين والجلسات
├── server.mjs           # الخادم، الحسابات والصلاحيات والتخزين
├── package.json
├── .env.example
├── .gitignore
└── README.md
```

ينشئ التشغيل مجلد `data/` الذي يحتوي قاعدة SQLite وملفات الموظفين. هذا المجلد وملف `.env` مستبعدان من Git. ملف ZIP المسلم لا يحتوي أي حسابات أو كلمات مرور أو ملفات موظفين تجريبية.

## رفع المشروع على GitHub

1. أنشئ مستودعًا جديدًا في حسابك على GitHub.
2. فك ملف ZIP وارفع **محتويات** مجلد `employee-portal` إلى المستودع، بما فيها `.gitignore` و`.env.example`.
3. لا ترفع `data/` أو `.env`. الاستبعاد في `.gitignore` يعمل مع Git؛ عند رفع الملفات يدويًا عبر المتصفح يجب استبعادها بنفسك.

لرفع الكود من الطرفية إلى مستودع فارغ، بعد استبدال الرابط برابط مستودعك:

```sh
git init -b main
git add .
git commit -m "Add Bushrakom employee portal"
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

**GitHub يحتفظ بالكود. GitHub Pages لا يشغّل خادم Node.js ولا يحفظ ملفات الموظفين.** تشغيل البوابة للموظفين يحتاج خادمًا فعليًا بقرص دائم، ولا يلزم ذلك لرفع المشروع ومراجعته على GitHub.

## تشغيلها على خادم

- شغّل نسخة واحدة من التطبيق على Node.js 24.14+، مع مساحة تخزين دائمة خاصة غير متاحة للويب. هذا الإصدار يستخدم SQLite وقرص الخادم؛ لا تنشره على خدمة تمسح القرص عند إعادة التشغيل أو على عدة نسخ تتشارك مجلد البيانات.
- اضبط `APP_ORIGIN` إلى رابط HTTPS الكامل دون مسار أو شرطة أخيرة، مثل `https://portal.example.org`، واضبط `HOST` بحسب الشبكة. اجعل خادم التطبيق خلف وكيل HTTPS، ولا تفتح منفذ التطبيق مباشرة للإنترنت.
- اضبط `DATA_DIR` إلى مسار خاص دائم، واحتفظ بالمجلد خارج `public/` والمستودع. تجنّب تغيير موقعه بعد إدخال البيانات دون نقل قاعدة البيانات والملفات معًا.
- اضبط حدود الرفع والمهل الزمنية في الاستضافة والوكيل لملف 1 جيجابايت. بعض الاستضافات تفرض حدًا أصغر من التطبيق.
- عند استخدام Nginx، أضف داخل الموقع الذي ينهي HTTPS (مع إعداد الشهادة والنطاق لدى مسؤول الخادم):

  ```nginx
  client_max_body_size 1g;
  location / {
      proxy_pass http://127.0.0.1:3000;
      proxy_request_buffering off;
      proxy_read_timeout 3600s;
      proxy_send_timeout 3600s;
      client_body_timeout 3600s;
      proxy_set_header Host $host;
  }
  ```

- حد التزامن الحالي 4 عمليات رفع. لا توجد حصة إجمالية لكل موظف؛ وفّر مساحة قرص ومراقبة للسعة.
- خلف وكيل واحد يُطبق حد محاولات الدخول بحسب عنوان الوكيل أيضًا. للتوسع المؤسسي اضبط تحديد المعدل في بوابة الشبكة مع تمرير العناوين الموثوق، بدل الوثوق بأي ترويسة يرسلها الزائر.
- يُفرض منع التضمين في إطارات، والتحقق من مصدر طلبات التعديل، وكوكي جلسة `HttpOnly` و`SameSite=Strict`، مع `Secure` عند HTTPS.
- تعطيل المشاركة أو إلغاء الإذن يمنع الطلبات اللاحقة؛ لا يسترجع نسخة سبق تنزيلها أو يقطع تنزيلًا بدأ بالفعل.
- لا يتضمن هذا الإصدار فحصًا آليًا للبرمجيات الضارة أو معاينة داخل المتصفح؛ تنزيل الملفات يكون كمرفقات.

## النسخ الاحتياطي

أوقف التطبيق إيقافًا سليمًا ثم انسخ **مجلد البيانات كاملًا** إلى مكان خاص محفوظ، بما يشمل قاعدة البيانات ومجلد `files`. استعد المجلد كاملًا قبل إعادة التشغيل. نسخ الكود وحده لا ينسخ ملفات الموظفين أو حساباتهم.

إذا توقف الخادم قسرًا أثناء الرفع، قد تبقى ملفات جزئية داخل `data/tmp`. يمكن تنظيف محتويات `tmp` بعد إيقاف التطبيق والتأكد من عدم وجود رفع جارٍ. لا تحذف قاعدة البيانات أو مجلد `files`.

## التحقق

```sh
npm test
```

الاختبارات تنشئ بيانات مؤقتة مستقلة وتمسحها بعد الانتهاء. تشمل الدخول وحدود كلمات المرور، صلاحيات المسؤول، منع حذف الحسابات، حماية آخر مسؤول، إلزام المجلد، منع رفع حجم معلن أكبر من الحد، عزل الملفات، أذونات الاطلاع وإغلاقها، تعديل الملفات وحذفها، إبطال الجلسات، مهلة الخمول، تنظيف الرفع المنقطع وتحديد محاولات الدخول. تستخدم اختبارات انتهاء الجلسة ساعة قابلة للتحكم بدل الانتظار 15 دقيقة.

تقنية التخزين: [SQLite المدمجة في Node.js](https://nodejs.org/docs/latest-v24.x/api/sqlite.html). هذا المشروع لا يحتاج خدمة قاعدة بيانات خارجية.

الصورة والشعار مرفقان بحسب طلب صاحب المشروع؛ تبقى حقوقهما للجهة المالكة. لا يتضمن المشروع ترخيصًا عامًا لإعادة توزيع الهوية أو استعمالها من جهات أخرى.
